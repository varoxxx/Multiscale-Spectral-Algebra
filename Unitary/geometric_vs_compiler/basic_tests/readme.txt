README — Geometric Unitary Collapse Framework
Last updated: 2026‑08‑26

This repository contains a collection of geometric collapse tests for unitary
matrices in U(N). Each script defines a manifold inside the unitary group and
performs geometric descent toward that manifold using:

• random perturbations
• QR re‑unitarization
• Frobenius‑norm energies
• acceptance‑based descent
• early stopping
• full unitarity audits

The framework validates that geometric descent behaves correctly across multiple
manifold types, including tensor, diagonal, block‑diagonal, stabilizer,
hardware‑efficient, and intersection manifolds.

----------------------------------------------------------------------
1. block_diagonal_collapse.py
----------------------------------------------------------------------

Collapse toward the block‑diagonal manifold.

Target:
    Unitaries composed of independent blocks (e.g., sizes [4,4], [8,8], etc.)

Projection:
    Extract block structure and compute block‑wise Frobenius energy.

Energy:
    E_bd(U) = || U − U_block ||_F²

Validates:
    Block structure, partial factorization, block‑wise geometry.

----------------------------------------------------------------------
2. block_stabilizer_collapse.py
----------------------------------------------------------------------

Collapse toward a stabilizer / Clifford‑like manifold.

Target:
    Unitaries that map Pauli operators to Pauli operators (up to phase).

Projection:
    Conjugate Pauli basis and measure Frobenius overlap.

Energy:
    E_stab(U) = − Σ_P max_j ( |⟨P_j, U P U†⟩_F| / ||U P U†||_F )

Validates:
    Pauli preservation, Clifford‑like structure, stabilizer geometry.

----------------------------------------------------------------------
3. diagonal_unitary_collapse.py
----------------------------------------------------------------------

Collapse toward the diagonal manifold.

Target:
    Unitaries close to diagonal matrices.

Projection:
    Extract diagonal part.

Energy:
    E_diag(U) = || U − diag(U) ||_F²

Validates:
    Diagonal structure, phase‑only unitaries, spectral geometry.

7. hardware_efficient_collapse.py
----------------------------------------------------------------------

Collapse toward the hardware‑efficient shallow‑circuit manifold.

Target:
    Shallow circuits composed of 1‑qubit and 2‑qubit gates on a linear chain.

Projection:
    Build circuit → QR re‑unitarize.

Energy:
    E_he(U) = || U − U_he ||_F²

Validates:
    Hardware‑efficient geometry, shallow circuit structure.

----------------------------------------------------------------------
8. intersection_manifold_collapse.py
----------------------------------------------------------------------

Collapse toward intersection manifolds, combining two energies:

    E_int(U) = α E_A(U) + (1 − α) E_B(U)

Supported intersections:
    • diagonal ∩ tensor
    • stabilizer ∩ hardware‑efficient
    • tensor ∩ hardware‑efficient
    • block‑diagonal ∩ hardware‑efficient

Validates:
    Multi‑manifold geometry,
    Compatibility of manifold energies,
    Stability of intersection descent,
    Generalization of collapse engine.

This script is the meta‑controller that uses all previous manifold energies.

9. circuit_extraction.py
----------------------------------------------------------------------

Extract an approximate hardware‑efficient circuit from a full unitary.

Purpose:
    Demonstrates that a unitary generated by a shallow hardware‑efficient
    circuit can be decomposed back into its constituent 1‑qubit and 2‑qubit
    gates using local SVD‑based projections.

Method:
    • Generate a target unitary U_target using hardware_efficient_projection.
    • For each qubit and each 2‑qubit edge, reshape U_target into
      (local × rest) blocks and perform an SVD.
    • Extract the dominant rank‑1 component and re‑unitarize via QR.
    • Embed each extracted gate into the full Hilbert space using
      kron_on_qubits.
    • Reconstruct a circuit U_recon from the extracted gates.

Validation:
    • Frobenius distance ||U_target − U_recon||_F
    • Direct unitarity check (U_recon U_recon† = I)
    • Determinant magnitude (≈ 1)
    • Eigenvalues on the unit circle
    • Column orthonormality
    • Hilbert–Schmidt fidelity

Notes:
    This test produces a *coarse but real* circuit approximation. It confirms
    that the extraction method is mathematically meaningful and that the
    reconstructed circuit is a true unitary, but it does not guarantee
    high‑fidelity recovery.

10. advanced_circuit_extraction.py
----------------------------------------------------------------------

Multi‑pass refinement of hardware‑efficient circuit extraction.

Purpose:
    Extends the basic extraction method with iterative refinement passes.
    After the initial extraction, the algorithm computes a residual matrix
    R = U_target U_recon† and extracts correction gates from R to update
    each layer of the circuit.

Method:
    • Perform initial SVD‑based extraction of all 1‑qubit and 2‑qubit gates.
    • Reconstruct U_recon from the extracted circuit.
    • Compute residual R = U_target U_recon†.
    • For each layer and each gate, extract correction gates from R using
      the same local SVD projection.
    • Update gates by composition (U_new = U_old · U_corr).
    • Repeat for multiple refinement passes.

Validation:
    • Frobenius distance after refinement
    • Direct unitarity (U_recon U_recon† = I)
    • Determinant magnitude (≈ 1)
    • Eigenvalues on the unit circle
    • Column orthonormality
    • Hilbert–Schmidt fidelity
    • Residual norm ||U_target U_recon† − I||_F

Notes:
    This test demonstrates a real, iterative circuit‑extraction algorithm.
    It confirms that the refinement process is stable, the reconstructed
    circuit remains unitary, and the approximation quality can be quantified.
    Like the basic test, it produces an approximate—not exact—recovery of
    the original hardware‑efficient circuit.

11. hardware_constrained_transpile_comparison.py
----------------------------------------------------------------------

Demonstration of algebraic compiler limitations under strict hardware constraints,
and geometric compiler robustness.

Purpose:
    This test highlights a practical limitation of algebraic quantum compilers
    (specifically Qiskit) when they are forced to compile a non‑local circuit
    onto a restrictive hardware topology such as a linear chain. Under these
    conditions, Qiskit may fail or crash due to internal constraints in its
    transpilation pipeline. The geometric compiler, which operates directly on
    unitary matrices rather than gate rules, continues to produce a valid
    unitary even when Qiskit cannot generate a hardware‑compatible circuit.

Method:
    • Construct a deliberately non‑local Qiskit circuit containing entangling
      operations between distant qubits and multiple layers of single‑qubit
      rotations.

    • Attempt to transpile the circuit to a strict linear‑chain coupling map.
      Qiskit is expected to fail under this configuration, often producing
      errors related to multi‑qubit gates (e.g., CCX) being incompatible with
      custom coupling maps. The test includes a safeguard to catch and report
      the failure; users may remove the safeguard to observe the crash directly.

    • Regardless of Qiskit’s transpilation outcome, obtain the unitary matrix
      of the original circuit using Qiskit’s simulator.

    • Feed this unitary into the geometric compiler, which applies multi‑pass
      SVD‑based extraction, kron embedding, and QR re‑unitarization to produce
      a reconstructed unitary.

    • Compute a simple observable, <Z_q>, on the geometric reconstruction.
      If Qiskit succeeded, compare the observable between Qiskit and the
      geometric compiler. If Qiskit failed, show that the geometric result
      remains well‑defined and unitary.

Validation:
    • Direct unitarity check (U_geo U_geo† = I)
    • Observable comparison (<Z_q>) when Qiskit succeeds
    • Error reporting when Qiskit fails
    • Demonstration that geometric reconstruction remains valid even when
      algebraic compilation is not possible

Notes:
    This test is not intended as a criticism of Qiskit. The failure arises
    because the test intentionally forces Qiskit into a configuration outside
    its supported compilation model. The purpose is to demonstrate that the
    geometric compiler does not rely on algebraic gate rules or hardware
    connectivity and therefore remains robust under extreme constraints.
    Users can inspect or modify the test to verify Qiskit’s behavior directly.

General Behavior Across All Scripts
----------------------------------------------------------------------

Each collapse test:

• generates a random unitary
• applies random perturbations
• re‑unitarizes via QR
• computes manifold energy
• accepts only energy‑reducing updates
• adjusts step size dynamically
• stops early when improvement stalls
• performs full unitarity audits
• prints timing, acceptance ratio, and Frobenius distances

All tests confirm:

• stable descent
• correct unitarity
• correct manifold behavior
• correct scaling
• correct intersection geometry
